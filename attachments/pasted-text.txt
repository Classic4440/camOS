PRIORITY 1 — SECURE THE APPLICATION

The current desk implementation has an anonymous-access security problem.

The existing desk policies allow anonymous users to read, insert, and update records.

Treat this as a critical vulnerability.

Audit the entire database.

Identify:

- All existing tables.
- Their current RLS status.
- Anonymous policies.
- Authenticated policies.
- Storage bucket permissions.
- Database functions.
- Exposed views.
- Public API access.

Do not assume the desk is the only exposed resource.

Create a secure authentication architecture using Supabase Auth.

Account requirements

Implement:

- Email/password sign-in.
- Email verification.
- Password recovery.
- Session persistence.
- Secure logout.
- Optional MFA.
- Account profile.
- Session management.
- Security event history.

Do not expose public registration after the initial owner account is provisioned.

Do not hardcode account credentials.

Do not put passwords, service-role keys, or Grok API keys in frontend source code.

Database ownership

Introduce ownership relationships for private data.

Every private record must belong to an authenticated owner.

Use auth.uid() in RLS policies.

Remove the old unrestricted anonymous policies rather than merely adding restrictive policies alongside them.

Implement ownership checks for:

- Desk records.
- Tasks.
- Music records.
- Classic Brand records.
- Financial records.
- Projects.
- Learning records.
- Decisions.
- Documents.
- Other private resources.

Create private storage policies for uploaded files.

Never rely on hiding navigation or displaying a login screen as a substitute for database security.

Migration safety

Before modifying the database:

1. Inspect the existing schema.
2. Back up existing records.
3. Design migration scripts.
4. Preserve existing information.
5. Test ownership policies.
6. Verify anonymous access is rejected.
7. Verify authenticated owner access works.

Do not delete user records during security migration.
